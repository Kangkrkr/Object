### **3. Best Case**: 캡슐화를 통한 객체 간 협력
**캡슐화(Encapsulation)** 개념을 적용하여 각 객체가 다른 객체의 내부 구현에 의존하지 않고, 필요한 메시지를 보내 요청만 수행하도록 개선합니다. 이를 통해 객체는 자신이 알고 있는 정보를 적극적으로 사용하고, 내부 작업 과정은 외부에 숨깁니다.

#### Best Case의 장점:
1. **캡슐화**:
    - `Order`는 `Cart`의 내부 구현을 몰라도 되고, 단지 `placeOrder` 메시지만 전달해 작업을 수행합니다.
    - `Cart`는 `PaymentProcessor`와 협력하여 결제를 처리합니다. `Order`는 협력 과정의 세부 구현을 알 필요가 없습니다.

2. **메시지 전달 중심 설계**:
    - 각 객체는 "메시지 요청(Request)"을 통해 작업을 위임함으로써 더 적은 정보를 노출합니다.

3. **유지보수성**:
    - 객체 간의 인터페이스가 잘 분리되어 있어, 내부 구현 변경 시 다른 객체에 영향을 미치지 않습니다.
