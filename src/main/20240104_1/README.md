- **Base Case**: 객체의 책임과 역할이 명확하지 않고, 결합도가 높은 설계.
- **Good Case**: 책임을 명확히 분리하여 "책임 중심" 설계로 발전.
- **Best Case**: 캡슐화와 메시지 전달 중심 설계를 통해 "객체 간 협력"의 이상적인 모습을 구현.

---

### 좋은 설계와의 비교

#### Bad Case vs Good Case
- **Bad Case**는 모든 로직과 데이터를 한 클래스가 처리하여, 코드 재사용성과 확장 가능성을 희생시켰습니다.
- 반면 **Good Case**나 **Best Case**는 각각의 객체가 적절한 역할과 책임을 갖고 협력하도록 설계되었습니다.

### 요약:
이 코드처럼 **하나의 클래스가 모든 책임을 직접 수행하는 설계**는 절대로 권장되지 않습니다. 이는 객체지향 설계의 **최악의 사례**로, 다음과 같은 문제가 있습니다:
1. **단일 책임 원칙 위반**: 하나의 클래스가 너무 많은 일을 처리합니다.
2. **캡슐화 부재**: 데이터와 동작이 하나의 클래스에서 명시적으로 드러납니다.
3. **확장 불가능**: 새로운 기능 추가 시 기존 코드를 계속 수정해야 하고, 수정 시 에러 발생 가능성이 높아짐.

위와 같은 최악의 설계는 **더 나은 협력 구조**로 분리하여 책임을 위임하도록 개선해야 합니다
